# AI 톤 체커 고도화 PRD
# 프로젝트: 이 말투 어때 (Check My Tone)
# 작성일: 2026-02-21

## 1. 배경 및 현황

### 서비스 현황
- 앱인토스(토스 미니앱) 플랫폼에서 운영 중인 AI 커뮤니케이션 도우미
- 현재 두 가지 모드: 메시지 생성(generate) + 말투 교정(correct)
- DAU: 10~50명
- 핵심 사용자: 50대 > 30대 초반 > 60대
- generate 모드 최근 출시, 데이터 수집 중

### 핵심 문제
- 이탈 원인: "쓸 이유가 없음" — 도구형 앱의 구조적 한계 (빈도 문제)
- 현재 커버리지: [상황 발생] → [고민] → [작성] → [전송] 중 고민(generate) + 작성(correct)만 담당
- 비어있는 영역: [전송 후] → [답장 해석] — "내가 보낸 말이 이상하지 않았을까" (보낸 후 불안)

### 방향성
"메시지 생성/교정 도구" → "커뮤니케이션 도우미"로 영역 확장

## 2. 고도화 항목

### 2.1 [최우선] AI 프롬프트 답변 품질 개선

#### 문제점 A: Correct 모드 교정문 품질 저하
- 교정문이 원문과 거의 동일 (쉼표/띄어쓰기만 변경 → 복사할 가치 없음)
- 사용자가 선택한 톤을 무시 ("부드럽게" 선택 → "격식 있는 표현" 제공)
- 3개 교정문 간 차이가 미미

현재 문제 예시:
- 입력: "딸래미 우리 앞으로 더 잘 지내도록하자" (자녀, 부드럽게)
- 나쁜 교정: "딸래미, 우리 앞으로 더 잘 지내도록 하자." (쉼표만 추가)
- 나쁜 교정: "딸, 앞으로 우리 더 잘 지내도록 합시다." (부드럽게인데 격식체)

기대하는 교정:
- "우리 딸, 앞으로 엄마도 더 노력할게. 우리 같이 잘 지내보자." (공감 추가)
- "딸래미, 요즘 좀 서먹했지? 앞으로 더 챙겨줄게." (맥락 구체화)
- "딸, 우리 밥이나 맛있는 거 먹으러 가자. 앞으로 더 잘 지내자!" (가벼운 접근)

#### 문제점 B: Correct 모드 category_scores 불필요
- category_scores (5개 카테고리 × 10개 세부항목)가 응답에 포함되지만 실질적 가치 없음
- AI 토큰을 대량 소모하여 교정문 품질에 집중하지 못하게 함
- 제거하여 토큰 예산을 교정문 품질 향상에 투자

#### 문제점 C: Generate 모드 엣지 케이스 처리
- 의미없는 입력 시 설교/훈계성 응답 생성
- AI가 입력을 "상대방의 발언"으로 오해하여 엉뚱한 메시지 생성

현재 문제 예시:
- 입력: "이용민바보멍청이똥깨" (상사, 단호하게)
- 나쁜 응답: "개인적인 표현은 자제해 주셨으면 합니다" (설교, 입력에 반응)
- 나쁜 응답: "그런 언행은 적절하지 않습니다" (도덕적 판단)

기대하는 응답:
- "팀장님, 솔직하게 말씀드리겠습니다. 최근 업무 방식에 대해 개선이 필요하다고 생각합니다."
- 감정(불만/분노)을 읽고 시나리오(상사)에 맞게 건강하게 표현하는 메시지

#### 변경 범위
- 백엔드: systemCorrect.ts, systemGenerate.ts, jsonSchemaCorrect.ts, zodCorrect.ts
- 프론트엔드: lib/schema.ts, pages/result/index.tsx, pages/suggestion/index.tsx
- Edge Function 재배포 필요

### 2.2 [중요] 대화 맥락 분석 기능 (review 모드)

#### 핵심 가치
50~60대 핵심 사용자의 고통점: "내가 보낸 말이 이상하지 않았을까" (보낸 후 불안 해소)

#### 기능 설명
사용자가 "보낸 메시지"와 "받은 답장"을 함께 입력하면, AI가 대화 맥락을 읽고 상대방의 감정/의도를 해석

#### 입력
- 시나리오 선택: 기존과 동일 (누구에게 보냈는지)
- 톤 선택: 제거 (review 모드에서는 불필요)
- 입력 필드 1: "내가 보낸 메시지" (최소 10자, 최대 500자)
- 입력 필드 2: "상대방의 답장" (최소 5자, 최대 500자)

#### AI 분석 결과
- 한줄 진단: "상대방은 기분 나빠하지 않았어요. 답변이 짧은 건 바빠서일 가능성이 높아요."
- 감정 해석: 상대방이 느꼈을 감정 + 근거
- 내 메시지 평가: 점수(0~100) + 잘한 점/아쉬운 점
- 후속 메시지 추천: 2~3개 (CopyCard로 복사 가능)

#### UI 변경
- 홈 SegmentedControl: [메시지 생성] [말투 교정] [대화 분석] (3탭)
- review 모드 선택 시 입력 영역 변경 (2개 TextArea)
- 결과: /suggestion 페이지에서 렌더링 (별도 /result 불필요)

#### 변경 범위
- 프론트엔드: constants/params.ts, stores/form.ts, pages/index.tsx, pages/suggestion/index.tsx, pages/loading/index.tsx, api/analyze.ts, lib/schema.ts
- 백엔드: index.ts, 신규 systemReview.ts, zodReview.ts, jsonSchemaReview.ts, openai.ts에 analyzeReview() 추가
- 사용량: 기존 daily_usage 동일 적용 (1회 분석 = 1회 차감)
- DB 변경: 없음

### 2.3 [필요] Analytics 이벤트 연동

#### 목적
사용자 행동 데이터 수집으로 기능별 리텐션/전환율 파악

#### 도구
Granite Analytics SDK (@apps-in-toss/framework 내장)
- Analytics.Press: 클릭 이벤트
- Analytics.Impression: 노출 이벤트
- Analytics.Screen: 화면 진입

#### 핵심 이벤트
- 화면 진입: 홈, 결과, 상세
- 모드 선택: generate / correct / review
- 시나리오/톤 선택
- 분석 요청 (CTA 클릭)
- 교정문/생성문 복사
- 광고 시청 완료/이탈

#### 볼륨
하루 미만 작업

### 2.4 [참고] Sentry 에러 정리

#### 확인된 프로덕션 이슈
- TONE-CHECKER-6 + N: 500자 초과 입력으로 Edge Function 에러 (클라이언트 검증 추가 완료)
- TONE-CHECKER-P: 광고 성공 로그가 error level로 분류 (captureMessage level 수정 필요 → 이미 수정됨)
- TONE-CHECKER-R + S: Android AdMob 광고 show 실패 연쇄 에러 (사용자 영향 없음, 중복 로깅 방지 가드 추가 필요)

## 4. 제약 조건

- 앱인토스 미니앱 플랫폼 정책 준수
- 라이트한 규모 유지 (과도한 복잡성 지양)
- 외부 서비스 인계 불가 (토스 정책)
- TDS (Toss Design System) 필수 사용
- 기존 사용량 정책 유지 (일 3회 무료 + 광고 5회 충전)
- Edge Function 배포 필요 (Supabase)

## 5. 성공 지표

- 프롬프트 개선: 교정문 복사율 증가, 엣지 케이스 에러 0건
- review 모드: 전체 분석 중 review 모드 비율 20% 이상
- 리텐션: 7일 재방문율 개선 (현재 기준 대비)
