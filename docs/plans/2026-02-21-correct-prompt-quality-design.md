# Correct 모드 프롬프트 품질 개선 설계

## 날짜: 2026-02-21

## 문제

Correct 모드의 교정문이 복사할 가치가 없음:

- 원문과 거의 동일 (쉼표/띄어쓰기만 변경)
- 사용자가 선택한 톤을 무시 ("부드럽게" 선택 → "격식 있는 표현" 제공)
- 3개 교정문 간 차이가 미미

### 근본 원인 (systemCorrect.ts)

1. `"3개는 각각 다른 방향 (부드럽게/격식있게/간결하게 등)"` → 사용자 톤 무시의 원인
2. `"text는 원문 구조 유지"` → 소극적 교정의 원인
3. 톤 반영 지시 부재

## 설계 방향

**"의도는 유지하되 표현은 자유롭게"**

- 50~60대 핵심 사용자는 "내 마음을 더 잘 표현해주는 도구"를 원함
- 원문의 핵심 의도는 100% 유지하되, 문장 구조는 자유롭게 재구성
- 선택한 톤을 3개 모두 반영, 접근법만 다르게

## 변경 사항

### 수정 파일: `systemCorrect.ts` (1개만)

스키마, UI, 백엔드 로직 변경 없음.

### 1. corrections 작성 규칙 교체

**Before:**

```
- 오탈자 먼저 검수 및 수정 (맞춤법, 띄어쓰기, 문법)
- 3개는 각각 다른 방향 (부드럽게/격식있게/간결하게 등)
- text는 원문 구조 유지, 마크업 금지, 복사-붙여넣기 가능한 완성 문장
```

**After:**

```
- 사용자가 선택한 톤(tone)을 3개 교정문 모두에 반영
- 3개는 각각 다른 접근법으로 작성:
  1. 공감형: 감정/공감 표현을 추가하여 따뜻하게
  2. 맥락형: 상황을 구체화하여 자연스럽게
  3. 행동형: 구체적 행동/제안을 담아 가볍게
- 원문의 "의도"는 반드시 유지하되, 문장 구조는 자유롭게 재구성
- 원문과 거의 같은 교정(쉼표/띄어쓰기만 변경)은 절대 금지
- 사용자가 바로 복사해서 보낼 수 있는 매력적인 문장 작성
```

### 2. label 규칙 변경

**Before:** 톤 기반 — "부드러운 표현", "격식 있는 표현", "간결한 표현"

**After:** 접근법 기반 — "공감형 표현", "맥락형 표현", "행동형 표현"

### 3. Few-shot 예시 추가

나쁜 교정과 좋은 교정을 대비하는 예시를 프롬프트에 포함.

```
[예시: 자녀에게, 부드럽게]
입력: "딸래미 우리 앞으로 더 잘 지내도록하자"

나쁜 교정 (금지):
- "딸래미, 우리 앞으로 더 잘 지내도록 하자." (쉼표만 추가 — 복사 가치 없음)
- "딸, 앞으로 우리 더 잘 지내도록 합시다." (부드럽게인데 격식체 — 톤 무시)

좋은 교정:
- 공감형: "우리 딸, 앞으로 엄마도 더 노력할게. 우리 같이 잘 지내보자."
- 맥락형: "딸래미, 요즘 좀 서먹했지? 앞으로 더 챙겨줄게."
- 행동형: "딸, 우리 밥이나 맛있는 거 먹으러 가자. 앞으로 더 잘 지내자!"
```

### 변경하지 않는 것

- category_scores 관련 규칙 전체
- signals / warnings 규칙
- 점수 규칙
- JSON Schema (jsonSchemaCorrect.ts)
- Zod 스키마 (zodCorrect.ts)
- 프론트엔드 코드

## 기대 효과

- 교정문 복사율 증가
- 선택한 톤 정확 반영
- 3개 교정문 간 확실한 차이 제공
