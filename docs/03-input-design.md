# 03. 입력 설계

## 1. 모드 탭

| 항목 | 메시지 생성 | 말투 교정 |
|------|----------|----------|
| 설명 | 상황을 설명하면 메시지를 만들어줌 | 보내려는 문장을 넣으면 톤을 교정 |
| 기본 선택 | **기본값** | - |
| 탭 전환 시 | 텍스트 입력만 초기화 (시나리오/톤 유지) | 동일 |

## 2. 시나리오 칩 (7개)

v1의 `relationship` (business/personal 2개) → v2의 `scenario` (7개)로 확장.
"자녀/부모"를 "자녀에게" + "부모에게"로 분리 — 존칭 방향과 톤 지시가 완전히 다르기 때문.

| 시나리오 | value | 타겟 연결 | AI 프롬프트 지시 |
|---------|-------|----------|-----------------|
| 자녀에게 | `to_child` | 50대+ 핵심 | "부모가 자녀에게 보내는 메시지. 잔소리가 아닌 따뜻한 관심으로, 세대 차이를 고려한 표현" |
| 부모에게 | `to_parent` | 20~30대 | "자녀가 부모에게 보내는 메시지. 예의 바르면서도 가깝고 따뜻한 표현" |
| 직장상사 | `boss` | 30대 핵심 | "직장 상사에게 보내는 메시지. 존댓말, 격식, 비즈니스 매너 준수" |
| 동료 | `colleague` | 30대 | "직장 동료 간 메시지. 친근하면서도 업무적 예의 유지" |
| 거래처 | `client` | 30대 | "비즈니스 외부 소통. 전문적이고 정중한 어조" |
| 친구 | `friend` | 전 연령 | "친구 간 대화. 편안하고 자연스러운 표현" |
| 연인 | `partner` | 전 연령 | "연인 간 대화. 다정하고 배려하는 표현" |

- **선택 방식**: 단일 선택 (필수)
- **기본값**: 없음 → 반드시 하나 선택해야 CTA 활성화
- **UI**: 2행 그리드 (상단 4개 + 하단 3개)

### 시나리오별 동적 플레이스홀더

시나리오 선택 시 텍스트 입력의 힌트가 변경된다. 50대+ 사용자에게 "뭘 입력해야 하는지" 가이드 효과.

| 시나리오 | 생성 모드 플레이스홀더 | 교정 모드 플레이스홀더 |
|---------|---------------------|---------------------|
| 자녀에게 | "자녀에게 걱정되는 마음을 전하고 싶어요" | "자녀에게 보내려는 문장을 입력해주세요" |
| 부모에게 | "부모님에게 감사한 마음을 전하고 싶어요" | "부모님에게 보내려는 문장을 입력해주세요" |
| 직장상사 | "상사에게 휴가 요청을 하고 싶어요" | "상사에게 보내려는 문장을 입력해주세요" |
| 동료 | "동료에게 업무 협조를 요청하고 싶어요" | "동료에게 보내려는 문장을 입력해주세요" |
| 거래처 | "거래처에 일정 변경을 알리고 싶어요" | "거래처에 보내려는 문장을 입력해주세요" |
| 친구 | "친구에게 미안한 마음을 전하고 싶어요" | "친구에게 보내려는 문장을 입력해주세요" |
| 연인 | "연인에게 서운한 마음을 전하고 싶어요" | "연인에게 보내려는 문장을 입력해주세요" |
| 미선택 | "어떤 상황인지 설명해주세요" | "보내려는 문장을 입력해주세요" |

## 3. 톤 칩 (4개)

v1의 `situation` (neutral/sensitive/casual 3개) → v2의 `tone` (4개)로 변경

| 톤 | value | AI 프롬프트 지시 |
|----|-------|-----------------|
| 부드럽게 | `soft` | "따뜻하고 배려하는 느낌. 상대방 감정을 고려한 표현" |
| 단호하게 | `firm` | "명확하고 확고한 느낌. 의사를 분명히 전달하되 무례하지 않게" |
| 격식있게 | `formal` | "존댓말, 공식적인 느낌. 높임 표현과 격식체 사용" |
| 캐주얼하게 | `casual` | "편하고 친근한 느낌. 반말이나 구어체 허용" |

- **선택 방식**: 단일 선택
- **기본값**: `soft` (부드럽게)

### 톤 4개 유지 근거

- 시나리오와 톤의 역할이 다름 (누구에게 vs 어떤 느낌으로)
- 50대+ 사용자는 "격식있게"를 명시적으로 선택하는 행위에서 안심감을 느낌
- 4개 선택지의 인지 부하가 크지 않음 (한 줄에 표시 가능)
- 추후 데이터로 안 쓰이는 톤을 빼는 건 쉽지만, 추가하면 재배포 필요

## 4. 텍스트 입력

### 가이드 텍스트

입력 영역 상단에 고정 가이드 텍스트를 표시하여 어떤 상황이든 입력 가능하다는 것을 안내.

| 모드 | 가이드 텍스트 |
|------|-------------|
| 메시지 생성 | "어떤 상황이든 편하게 설명해주세요" |
| 말투 교정 | "보내려는 문장을 그대로 입력해주세요" |

### 동적 힌트 (글자수 기반)

입력 영역 하단에 글자수에 따라 변하는 힌트를 표시하여, 길고 상세한 입력이 더 좋은 결과를 만든다는 것을 자연스럽게 전달.

**메시지 생성 모드:**

| 글자수 | 힌트 텍스트 | 색상 |
|--------|-----------|------|
| 0 ~ 최소 미만 | (없음) | - |
| 최소(10자) ~ 30자 | "상황을 더 자세히 적으면 결과가 좋아져요" | grey400 |
| 30 ~ 100자 | "좋아요! 충분한 정보예요" | blue500 |
| 100자+ | "아주 좋아요! 맞춤 메시지를 만들 수 있어요" | blue600 |

**말투 교정 모드:**

| 글자수 | 힌트 텍스트 | 색상 |
|--------|-----------|------|
| 0 ~ 최소 미만 | (없음) | - |
| 최소(20자) ~ 50자 | "문장이 길수록 더 정확한 교정이 가능해요" | grey400 |
| 50 ~ 150자 | "좋아요! 충분한 문장이에요" | blue500 |
| 150자+ | "아주 좋아요! 정확한 톤 분석이 가능해요" | blue600 |

### 입력 필드 스펙

| 항목 | 메시지 생성 | 말투 교정 |
|------|----------|----------|
| 플레이스홀더 | 시나리오별 동적 변경 | 시나리오별 동적 변경 |
| 최소 글자수 | 10자 | 20자 (현행 유지) |
| 최대 글자수 | 800자 | 800자 (현행 유지) |
| 글자수 표시 | 동적 힌트 옆 `{현재}/{최대}` | 동일 |

## 5. CTA 버튼

### 활성화 조건

```
활성화 = 시나리오 선택됨 AND 텍스트 길이 >= 최소 글자수
```

| 상태 | 버튼 텍스트 | 스타일 |
|------|-----------|--------|
| 비활성화 (생성) | "생성하기" | disabled |
| 비활성화 (교정) | "교정하기" | disabled |
| 활성화 (생성) | "생성하기" | primary |
| 활성화 (교정) | "교정하기" | primary |

### 잔여 횟수 & 광고 충전 표시

- 홈 상단에 `오늘 남은 횟수: N회` 항상 표시
- **잔여 1회 이하일 때** 충전 아이콘 노출 → 탭 시 AdBottomSheet
- 0회일 때 CTA 버튼 대신 UsageLimitNotice 배너 표시

> v1에서는 무료 3회 전부 소진 후에만 광고 노출.
> v2에서는 잔여 1회부터 충전 안내를 노출하여 자연스러운 전환 유도.
> 상세 수익 전략은 `06-revenue-strategy.md`에서 다룸.

## 6. v1 → v2 코드 매핑

```
v1                          v2
─────────────               ─────────────
relationship (2개)    →     scenario (7개)
  business                    to_child, to_parent, boss, colleague, client
  personal                    friend, partner

situation (3개)       →     tone (4개)
  neutral                     soft (≈ neutral)
  sensitive                   firm (≈ sensitive)
  casual                      casual (유지)
                              formal (신규)

(없음)                →     mode
                              generate (신규)
                              correct (≈ v1 기본)
```

## 7. Form Store 변경안

```typescript
type Mode = 'generate' | 'correct';
type Scenario = 'to_child' | 'to_parent' | 'boss' | 'colleague' | 'client' | 'friend' | 'partner';
type Tone = 'soft' | 'firm' | 'formal' | 'casual';

type FormState = {
  mode: Mode;
  scenario: Scenario | null;   // 필수 선택, 기본값 null
  tone: Tone;                  // 기본값 'soft'
  text: string;

  setMode: (mode: Mode) => void;
  setScenario: (scenario: Scenario) => void;
  setTone: (tone: Tone) => void;
  setText: (text: string) => void;
  reset: () => void;
};
```
