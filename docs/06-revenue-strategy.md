# 06. 수익 전략

## 1. 현행 모델 (v1)

| 항목 | 값 |
|------|-----|
| 무료 사용 | 1일 3회 |
| 보상 광고 충전 | 광고 1회 시청 → 1회 충전 (최대 5회) |
| 광고 노출 조건 | 무료 3회 **전부 소진 후**에만 노출 |
| 리셋 | 매일 자정 (로컬 시간) |
| 인터스티셜 광고 | 로딩 화면에서 항상 노출 |

### v1 실적 (2026.01.14~02.14)

| 지표 | 값 |
|------|-----|
| 광고 참여율 | 3.3% |
| 1인당 사용 횟수 | 1.71 |

**문제점:**
- 대부분 사용자가 1~2회만 쓰고 이탈 → 3회 소진 전에 떠남
- 광고 충전 UI를 한 번도 못 보는 사용자가 대다수
- 보상 광고 존재 자체를 모르는 상태

## 2. v2 변경 사항

### 광고 노출 조건 변경 (B안 채택)

| 항목 | v1 | v2 |
|------|----|----|
| 노출 시점 | 3회 전부 소진 후 | **잔여 1회 이하부터** |
| 노출 위치 | UsageLimitNotice만 | 홈 상단 잔여 횟수 옆 충전 아이콘 |
| 0회 도달 시 | UsageLimitNotice | UsageLimitNotice (유지) |

### 구현 상세

```
잔여 횟수 >= 2회:
  [오늘 남은 횟수: N회]

잔여 횟수 == 1회:
  [오늘 남은 횟수: 1회  ⚡충전]  ← 충전 아이콘 노출

잔여 횟수 == 0회:
  [UsageLimitNotice 배너]
  └─ "충전하기" → AdBottomSheet
```

### 기대 효과

- 3회 소진 전 광고 존재를 인지 → 자연스러운 전환
- "갑자기 0회" 충격 완화
- 광고 참여율 목표: 3.3% → 10%+

## 3. 무료/보상 쿼터 유지

v2에서 쿼터 수치는 변경하지 않는다.

| 항목 | 값 | 유지 근거 |
|------|-----|----------|
| 무료 3회 | 유지 | 메시지 생성 추가로 사용 빈도 상승 예상 → 3회면 "부족함"을 느끼기 충분 |
| 보상 5회 | 유지 | 일 최대 8회(3+5)는 적정 수준 |
| 자정 리셋 | 유지 | 변경 불필요 |

## 4. 인터스티셜 광고 (로딩 화면)

현행 그대로 유지:
- 로딩 화면에서 API 호출과 광고 로딩 병렬 실행
- 2-phase 타임아웃 (8s load + 3s show)
- 모든 분석/생성 요청에 노출

## 5. 향후 수익 모델 검토 (v2 이후)

v2에서는 광고 모델만 유지하되, 데이터 수집 후 아래 옵션 검토:

| 모델 | 적용 시점 | 조건 |
|------|----------|------|
| 구독 (월정액) | DAU 100+ 달성 후 | 무제한 사용 + 광고 제거 |
| 쿼터 증량 유료화 | DAU 50+ 달성 후 | 일 20회 등 대량 패키지 |
| 프리미엄 톤 | 기능 안정화 후 | 비즈니스 전용 톤, 이메일 형식 등 |

> v2 단계에서는 구현하지 않음. 데이터 확인 후 판단.

## 6. 데이터베이스 변경

### daily_usage 테이블 — 변경 없음

현행 스키마가 v2 요구사항을 모두 충족:
- `free_limit`, `used_count`: 무료 쿼터 관리
- `rewarded_limit`, `rewarded_count`, `rewarded_used_count`: 보상 쿼터 관리

### RPC 변경

| RPC | 변경 |
|-----|------|
| `rpc_get_today_status` | 변경 없음 |
| `use_analysis_once` | 변경 없음 (생성/교정 구분 없이 동일 차감) |
| `rpc_reward_once` | 변경 없음 |

> 생성 모드와 교정 모드를 구분하여 사용량을 집계하고 싶다면, `daily_usage`에 `generate_count`/`correct_count` 컬럼을 추가할 수 있으나 v2에서는 불필요. 추후 데이터 분석 필요 시 추가.
